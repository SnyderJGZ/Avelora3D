## 1. Recibir `CombatEvent` (`NetworkClient.cs`)

En el `switch` de mensajes (junto a `case MessageType.Snapshot:`, ~línea 1124) añade:

```csharp
case MessageType.CombatEvent:
    if (_welcomeReceived &&
        MessageCodec.TryReadCombatEvent(buffer, offset, length, out CombatEventMessage combatEvent))
    {
        HandleCombatEvent(combatEvent);
    }

    break;
```

`HandleCombatEvent` recorre `Entries` y, por cada uno:

1. Busca la posición actual del atacante y del objetivo con un helper nuevo
   `bool TryGetEntityPosition(int entityId, out Vector3 position)`: si `entityId == _entityId`, es
   `transform.position`; si no, `_remoteViews.TryGetValue(entityId, out RemotePlayerView view)` y
   `view.transform.position`. Si no encuentra el **objetivo**, ignora la entrada (no se ve).
2. Si `(Flags & CombatEventFlags.Ranged) != 0` **y** encuentra al atacante → crea un proyectil (§2). El número
   de daño sale cuando el proyectil llega.
3. Si no → crea el número de daño (§3) ya, sobre el objetivo.

Al desconectar o volver a la selección de personaje (donde hoy se limpian `_remoteViews`), vacía también las dos
listas de efectos.

## 2. Proyectil cosmético

Struct privado `CombatProjectile { int AttackerId; int TargetId; Vector3 From; float StartTime; float Duration; ushort Damage; CombatEventFlags Flags; }`
y una lista `private readonly List<CombatProjectile> _projectiles = new List<CombatProjectile>(32);`.

- `From` = posición del atacante al recibir el evento. El destino se lee **cada frame** con
  `TryGetEntityPosition(TargetId, …)` (sigue al objetivo); si el objetivo ya no existe, el proyectil se quita sin número.
- `Duration = Mathf.Clamp(distancia / 20f, 0.08f, 0.3f)` (20 tiles/s; el golpe ya ocurrió en el servidor,
  así que el proyectil es corto a propósito).
- Tope 32: si está lleno, quita el más antiguo (`RemoveAt(0)`) antes de añadir.
- En `Update` (o donde se actualicen las vistas cada frame) avanza: cuando `Time.unscaledTime - StartTime >= Duration`,
  quítalo y crea el número de daño sobre el objetivo (§3).
- Dibujo en `OnGUI` (§4): un cuadrado de 6×6 px en la posición interpolada `Vector3.Lerp(From, destino, t)`;
  color `new Color(0.95f, 0.85f, 0.5f)` si es físico, `new Color(0.5f, 0.8f, 1f)` si lleva `Magical`. Usa
  `GUI.color` + `GUI.DrawTexture(rect, Texture2D.whiteTexture)` como ya se hace en `NetworkClient.Gui.cs`
  (~línea 157) y restaura `GUI.color`.

## 3. Números de daño flotantes

Struct privado `DamageNumber { Vector3 Position; float StartTime; string Text; bool OnSelf; }` y
`private readonly List<DamageNumber> _damageNumbers = new List<DamageNumber>(32);` con tope 32 igual que arriba.

- `Position` = posición del objetivo al crearlo (no lo sigue). `Text = Damage.ToString()`, y si lleva
  `Killed` añade `"!"`. `OnSelf = TargetId == _entityId`.
- Dura 0,9 s: sube 0,8 unidades de mundo en ese tiempo y el alfa baja de 1 a 0 linealmente.
- Color: rojo `new Color(1f, 0.35f, 0.3f)` si `OnSelf` (daño que recibe el jugador), blanco si no.
- Un `GUIStyle` propio `_damageNumberStyle` (negrita, centrado, tamaño 16) creado una vez en `EnsureOverlayStyles`
  como los demás estilos.
- Un daño 0 también se muestra («0»): es información útil (golpe mitigado entero).

## 4. Dibujo (`NetworkClient.Gui.cs`)

## 5. Ataque con doble clic a la distancia del arma

Ya existe: `ApproachTarget` (~línea 768) camina hasta `range * ApproachFraction` y `HandleCombatInput`
(~línea 604) no envía fuera de `CurrentWeapon`. Con el arco a 6 el jugador ya se para a ~5,1. **Compruébalo y
dilo en el informe**; lo que falta es la línea de visión, para no plantarse detrás de una pared:

- Helper `bool HasLineOfSightTo(RemotePlayerView target)`: `true` si `_map == null || _map.Grid == null`; si no,
  `_map.Grid.HasLineOfSight(new Vec2(transform.position.x, transform.position.y), new Vec2(target.transform.position.x, target.transform.position.y))`.
  Comprueba el constructor real de `Vec2` en `shared/Avelora.Shared/Core/Vec2.cs`.
- `ApproachTarget`: solo se para (`return` con dirección cero) si está dentro de `stop` **y** `HasLineOfSightTo(target)`;
  sin vista sigue andando en línea recta como hoy (el `shortcut:` del comentario sigue valiendo: añade «o
  detrás de una pared sin vista»).
- `HandleCombatInput`, tras la comprobación de alcance y antes de `EncodeAttack`: si `!HasLineOfSightTo(target)`
  → en manual (`!_autoAttack`) `ShowHint("sin línea de visión")`; en los dos casos `return` sin enviar.
