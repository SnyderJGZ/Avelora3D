## Decisiones tomadas (no las cambies)

1. **Cuatro tipos, `StatusKind`: `Bonus = 1`, `Shield = 2`, `Slow = 3`, `Taunt = 4`.** Una entidad tiene **como mucho
   un estado de cada tipo** (tope por entidad = 4 = `ProtocolConstants.MaxStatusEffects`). Se guardan en un array fijo
   de 4 huecos indexado por `kind - 1`.
2. **Acumulación: se queda el más fuerte.** Si el tipo ya está activo y la cantidad nueva es **menor** que la actual
   (en el escudo, la que le **queda**), el nuevo se **ignora** (la habilidad se cobra igual; contador
   `StatusesIgnoredWeaker`). Si es igual o mayor, **sustituye** cantidad, lanzador y caducidad (refresca). Nunca se
   apila. La provocación tiene cantidad 0: la más reciente siempre gana.
3. **Duración en ticks:** `StatusTicks = ⌈statusSeconds × TickRate⌉`. Aplicado en el tick `T` → `ExpiresAtTick = T +
   StatusTicks`. Caducan en el servidor al **principio** del tick (`StatusSystem.Tick`, antes del movimiento) cuando
   `tick >= ExpiresAtTick`.
4. **La muerte limpia todos los estados** (al principio del tick siguiente, en `StatusSystem.Tick`). **No se guardan
   en la base**: al desconectar se pierden y la reconexión empieza sin estados (entidad nueva).
5. **Reglas de objetivo:**
   - **Dañinos (`Slow`, `Taunt`):** el mismo `CheckTarget` que un golpe (PvP efectivo de los dos, zonas seguras, PNJ en
     `Return`). `Taunt` solo a PNJ: con un jugador como objetivo → `InvalidTarget` (sin gasto).
   - **Beneficiosos (`Bonus`, `Shield`):** la regla de la cura de I-17: uno mismo o un jugador vivo; `PvpNotAllowed` si
     el objetivo tiene PvP efectivo y el lanzador no; la zona segura no lo impide; alcance y visión salvo sobre uno
     mismo. Sin comprobación de vida llena.
6. **Bonus = modificador de estadísticas, no de atributos base:** `+A` al **daño bruto** (ataque básico y habilidades
   de daño; no a curas ni escudos) y `+A` a **defensa y resistencia mágica**. Así no cambian vida ni recurso máximos y
   no hay nada que recortar al caducar. `Stats` lo refleja: el servidor reenvía `Stats` cuando cambia el bonus.
7. **Escudo después de la mitigación:** daño bruto → mitigación (defensa o resistencia, + bonus) → **escudo** → vida.
   El escudo son puntos de vida efectivos. Cantidad: misma fórmula que la cura (`GetAttackDamage` con
   `statusAmount` como base, escala con el atributo principal). Lo absorbido va en un `CombatEvent` aparte con la
   bandera nueva `Absorbed = 16`; la entrada normal solo sale si queda daño > 0. El escudo se agota a 0 y desaparece.
8. **Ralentización también a jugadores (PvP).** Reduce la velocidad un `statusAmount` % (10..80). Velocidad efectiva,
   igual en servidor, PNJ y cliente: `pct == 100 ? speed : speed * pct / 100f`. **El cliente se entera por un mensaje
   fiable propio, `StatusEffects`**, que lleva `SpeedPercent`; el cliente llama a `ClientPrediction.SetSpeed` y la
   reconciliación reaplica los inputs pendientes con la velocidad nueva. Coste: **una** corrección pequeña al empezar
   y otra al acabar (≈ Δvelocidad × inputs pendientes × dt: 1.6 × 4 × 0.05 = 0.32 tiles con 4 pendientes, por debajo
   del salto de 0.5), suavizada como cualquier otra. Los bots hacen lo mismo.
9. **Provocar:** el PNJ pasa a `Chase` con `TargetEntityId` = lanzador. Hoy nada cambia el objetivo de un PNJ en
   `Chase`/`Attack` (el daño solo da aggro en `Wander`), así que queda fijado mientras dure, salvo otra provocación.
   Correa, zona segura, muerte o marcha del lanzador → `Return` como hoy, y `StatusSystem` **quita** la provocación
   (contador `TauntsBroken`) si el PNJ está en `Return` o su objetivo ya no es el lanzador. Al caducar **no** vuelve al
   objetivo anterior (no hay tabla de amenaza).
10. **El snapshot no cambia.** Un byte más por entidad bajaría `MaxEntitiesPerSnapshot` de 67 a 63. En su lugar:
    - **Los demás:** mensaje nuevo `StatusEvent` (fiable, 2 + 5 B por entrada `{entityId, máscara}`), solo cuando
      cambia la máscara de una entidad, a quien la ve (mismo filtro que `CombatEvent`). Iconos sin duración. Límite
      aceptado: quien entra en la vista de una entidad ya afectada no ve sus iconos hasta el siguiente cambio (≤ 30 s).
    - **Uno mismo:** `StatusEffects` (fiable, solo al dueño, 3 + 7 B por estado) con tipo, habilidad, ticks restantes
      y cantidad, cada vez que cambia su lista (aplicar, refrescar, caducar, absorber, morir).
11. **Reparto (tabla §0.8 del diseño):** Guerrero **Provocar**; Mago **Rayo helado** (daño + ralentización) y **Escudo
    arcano**; Sanador **Bendición** (bonus). El ranger no recibe nada aquí: su «Tiro debilitante» reutilizará el
    modificador en I-19.
12. **`effect: "none"`** (nuevo): habilidad sin daño ni cura, solo estado. En `SkillCatalogEntry.Effect` vale 2.

    para <status>.`

    (int)Math.Ceiling(StatusSeconds * SimulationConstants.TickRate)`.

## 3. Estados de una entidad (`server/Avelora.Server/Entities/StatusEffects.cs`, nuevo)

```csharp
public struct ActiveStatus { public ushort SkillId; public int SourceId; public int Amount; public long ExpiresAtTick; }

/// <summary>Estados temporales de una entidad: uno por tipo, como mucho cuatro (I-18).</summary>
public sealed class StatusEffects
{
    private readonly ActiveStatus[] _slots = new ActiveStatus[ProtocolConstants.MaxStatusEffects]; // índice kind - 1
    public int Version { get; private set; }            // sube con cada cambio visible para el dueño
    public bool IsActive(StatusKind kind)                // _slots[k].ExpiresAtTick > 0
    public ActiveStatus Get(StatusKind kind)
    public byte Mask { get; }                            // bit (kind - 1) por cada activo
    public int SpeedPercent { get; }                     // Slow activo ? 100 - Amount : 100
    public int Bonus { get; }                            // Bonus activo ? Amount : 0
    public bool Apply(StatusKind kind, ushort skillId, int sourceId, int amount, long expiresAtTick)
    public int Absorb(int damage)
    public bool Remove(StatusKind kind)
    public int Expire(long tick)
    public int Clear()
}
```

- `Apply`: `kind` fuera de 1..4 o `expiresAtTick <= 0` → `ArgumentOutOfRangeException`. Activo y `amount <
  actual.Amount` → `false` sin tocar nada. Si no, sobrescribe el hueco, `Version++`, `true` (decisión 2).
- `Absorb`: sin escudo o `damage <= 0` → 0. Si no, `taken = Math.Min(damage, Amount)`; `Amount -= taken`; si queda 0,
  el hueco vuelve a `default`; `Version++`; devuelve `taken`.
- `Remove`, `Expire(tick)` (quita los activos con `tick >= ExpiresAtTick`), `Clear()`: devuelven cuántos quitaron (o
  si quitó) y hacen `Version++` solo si quitaron algo.
- `Entity` (`server/Avelora.Server/Entities/Entity.cs`): `public StatusEffects Statuses { get; } = new
  StatusEffects();` e `internal byte StatusMaskSent { get; set; }`.
- `PlayerEntity` (junto a `ResourceSentKey` ~120): `internal int StatusSentVersion { get; set; }` e
  `internal int BonusSent { get; set; }`.
