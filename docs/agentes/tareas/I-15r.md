## Qué cambia y por qué

El usuario pide que el temporizador de PvP forzado (los 5 minutos tras salir de la arena) se **cancele en el
momento en que el jugador entra en una zona segura**. Antes seguía corriendo dentro de la ciudad. Motivo: las
zonas PvP estarán lejos de las ciudades, y el forzado no debe durar dentro de una ciudad.

Decisión ya tomada: la espera de 30 s o 60 s se decide con el **PvP efectivo que tenía el jugador justo antes de
cancelar** (modo elegido PvP, o forzado restante > 0). Quien llega con el forzado activo espera 60 s.

## A. Servidor

Solo cambia **`server/Avelora.Server/Simulation/PvpSystem.cs`**, método `Tick`, **primer bucle** (el que recorre
los jugadores antes de las acciones `SetPvpMode`). No cambian `PlayerEntity`, `ServerConfig`, `server.json`,
`tools/carga/server-carga.json`, `Zone.cs`, `Program.cs`, `ConsoleReporter.cs` ni `NetworkServer.cs`. No cambies
la firma de `BuildStatus(PlayerEntity)`.

Sustituye el bloque de actualización del forzado y de la zona segura de ese bucle por exactamente esto
(conserva el resto del bucle):

```csharp
if (player.ZoneKind == ZoneKind.Pvp)
{
    player.PvpForcedTicksLeft = _forcedTicks;
}
else if (player.ZoneKind == ZoneKind.Safe && player.SafeZoneTicks == 0)
{
    // Entrada en segura: se decide con el PvP efectivo previo y se cancela el forzado.
    player.SafeZoneWaitTicks = player.PvpMode == PvpMode.Pvp || player.PvpForcedTicksLeft > 0
        ? _modeChangeFromPvpTicks
        : _modeChangeTicks;
    player.PvpForcedTicksLeft = 0;
}
else if (player.PvpForcedTicksLeft > 0)
{
    player.PvpForcedTicksLeft--;
}

if (player.ZoneKind == ZoneKind.Safe)
{
    if (player.SafeZoneTicks < player.SafeZoneWaitTicks)
    {
        player.SafeZoneTicks++;
    }
}
else
{
    player.SafeZoneTicks = 0;
}
```

Orden en cada tick: (1) `Zone` ya ha fijado `ZoneKind` del jugador; (2) este bucle cancela el forzado al entrar y
fija la espera; (3) el bucle de `SetPvpMode` usa `SafeZoneWaitTicks`; (4) el envío de `PvpStatus` compara la clave
y, al cambiar `Forced` de `Timer`/`InZone` a `None`, envía el estado en ese mismo tick.

Consecuencias que deben cumplirse: dentro de la segura `PvpForcedTicksLeft` es siempre 0; al salir de la segura
`SafeZoneTicks = 0` como hasta ahora; `PvpEffective` dentro de la segura es falso salvo que el modo elegido sea PvP
(en ese caso no hay forzado, pero el modo elegido sigue contando como PvP efectivo mientras esté en PvP).

**Persistencia:** no se cambia código. `NetworkServer` guarda `PvpForcedTicksLeft` tal cual, así que un jugador que
se desconecta en la ciudad (después de su primer tick dentro) guarda `PvpForcedSeconds = 0`. Lo demuestra la prueba
nueva de C.4.
