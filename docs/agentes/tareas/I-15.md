## Decisiones tomadas (no las cambies)

1. **La lista de zonas va en un mensaje propio `ZoneList`, enviado justo después del `Welcome`**, no dentro de él.
   El `Welcome` es de tamaño fijo (69 B) y lo comprueban con tamaño exacto el cliente, los bots y decenas de
   pruebas; un mensaje aparte en el mismo canal fiable y ordenado llega igual «con el Welcome», no rompe nada y se
   codifica una vez al arrancar. **Solo se envía si hay zonas** (con 0 zonas no hay mensaje: las pruebas de red
   existentes no cambian; el cliente vacía sus zonas al recibir el `Welcome`).
2. **`ZoneChanged` solo al cambiar.** Todo jugador empieza en `ZoneId = 0` (normal); el primer tick en que su
   casilla tiene otra zona (p. ej. aparece en la ciudad) se envía `ZoneChanged`. Aparecer en zona normal no envía nada.
3. **Sin exclusiones ni nombres en la red.** Una ciudad con hueco se hace con varios rectángulos; el rótulo del
   cliente solo necesita el tipo. El `name` vive en el JSON para leerlo y para los errores.
4. **La IA trata la zona segura como pared** con una segunda rejilla de colisión solo para PNJ (mapa + casillas
   seguras bloqueadas). Reutiliza `MovementSimulator.Step` sin tocarlo.
5. **`zonesPath` vacío por defecto** (= todo normal, el servidor arranca igual). Con ruta, el archivo tiene que
   existir y ser válido, como `npcs.json`.

## 1. Tipos compartidos y protocolo v19 (`shared/Avelora.Shared/Protocol/`)

**`Messages.cs`** (junto a `LootGainedMessage`):

```csharp
public enum ZoneKind : byte { Normal = 0, Safe = 1, Pvp = 2 }

public readonly struct ZoneRect      // casillas del mapa; X/Y esquina inferior izquierda
{ public ZoneRect(short x, short y, short width, short height) ... X, Y, Width, Height }

public readonly struct ZoneInfo      // Kind solo Safe o Pvp; Rects null → Array.Empty
{ public ZoneInfo(ushort id, ZoneKind kind, ZoneRect[] rects) ... Id, Kind, Rects }

public readonly struct ZoneListMessage    { ZoneInfo[] Zones }   // null → Array.Empty
public readonly struct ZoneChangedMessage { ushort ZoneId; ZoneKind Kind }
```

**`ProtocolConstants.cs`:** `Version = 19`; `MaxZones = 32`; `MaxZoneRectsPerZone = 16`; `MaxZoneRects = 128`.

**`MessageType.cs`:** `ZoneList = 30` (S → C) y `ZoneChanged = 31` (S → C), con su comentario.

**`MessageCodec.cs`** (mismo estilo que `EncodeLootGained`/`TryReadLootGained`; `WireWriter`/`WireReader` no tienen
`Int16`: escribe `WriteUInt16(unchecked((ushort)v))` y lee `(short)reader.ReadUInt16()`):

- `ZoneList`: tipo (u8) + N (u8) + N × [id (u16), kind (u8), R (u8), R × (x, y, w, h: i16 cada uno)].
  **2 + 4·N + 8·ΣR bytes** (máximo 2 + 128 + 1024 = 1154 B < `MaxMessageSize`).
  - `EncodeZoneList(in ZoneListMessage)`: `ArgumentOutOfRangeException` si N > 32, algún R == 0 o R > 16,
    ΣR > 128, `Id == 0`, `Kind` distinto de `Safe`/`Pvp`, o `Width`/`Height` <= 0. N = 0 es válido (2 B).
  - `TryReadZoneList(byte[] buffer, int offset, int length, out ZoneListMessage)`: `false` con tipo distinto,
    las mismas condiciones, o longitud distinta de la calculada.
- `ZoneChanged`: tipo (u8) + zoneId (u16) + kind (u8). **4 B.**
  - Válido solo si (`ZoneId == 0` y `Kind == Normal`) o (`ZoneId > 0` y `Kind` es `Safe`/`Pvp`).
    `EncodeZoneChanged` lanza `ArgumentOutOfRangeException` si no; `TryReadZoneChanged` devuelve `false` si no,
    con tipo distinto o longitud ≠ 4.

## 2. `ZoneMap` (archivo nuevo `server/Avelora.Server/Zones/ZoneMap.cs`, namespace `Avelora.Server.Zones`)

**JSON** (`zones.json`), clases DTO en el mismo archivo con el estilo de `NpcCatalog` (mismas `JsonOptions`,
propiedades `{ get; set; }` en camelCase):

```json
{ "zones": [ { "id": 1, "name": "…", "kind": "safe", "rects": [ { "x": -10, "y": -3, "w": 8, "h": 7 } ] } ] }
```

Clase `public sealed class ZoneMap`:

```csharp
public static readonly ZoneMap Empty;                       // sin zonas; KindAt siempre Normal
public static ZoneMap Load(string path, MapCollisionGrid map)  // lee, valida y precalcula
public static ZoneMap FromDefinitions(IReadOnlyList<ZoneDefinition> zones, MapCollisionGrid map) // lo usa Load y las pruebas
public ZoneInfo[] Zones { get; }                            // ya en formato de red, en el orden del archivo
public int RectCount { get; }
public ushort ZoneIdAt(float x, float y)                    // 0 = normal
public ZoneKind KindAt(float x, float y)
public MapCollisionGrid BuildNpcCollision(MapCollisionGrid map)
public void ValidateSpawners(NpcCatalog npcs)
```

- **Load:** ruta vacía → `ArgumentException`; archivo inexistente → `FileNotFoundException` con
  `"No se encuentra el archivo de zonas '<ruta>'. Corrige zonesPath o déjalo vacío para jugar sin zonas."`;
  JSON nulo → `InvalidOperationException("zones.json está vacío o no contiene un objeto.")`; `zones` nulo → lista vacía.
- **Validación** (`InvalidOperationException`, mensajes que empiecen por `"zones.json: "` y digan la zona por su
  `id`): como mucho 32 zonas; `id` entre 1 y 65535 y sin repetir; `name` no vacío; `kind` exactamente `"safe"` o
  `"pvp"` (minúsculas; `"normal"` se rechaza: es lo de por defecto); entre 1 y 16 rectángulos por zona y 128 en
  total; `w` y `h` >= 1; cada rectángulo dentro del mapa:
  `x >= map.OriginX`, `y >= map.OriginY`, `x + w <= map.OriginX + map.Width`, `y + h <= map.OriginY + map.Height`
  (calcúlalo en `long`), y `x`, `y`, `w`, `h` caben en `short`.
- **Precálculo:** `byte[] _tileZone` de `map.Width * map.Height` (0 = ninguna, si no índice + 1 en `Zones`),
  más `OriginX/OriginY/Width/Height`. Recorre las zonas en orden y cada casilla de cada rectángulo: la marca si
  está vacía o si la nueva tiene **más prioridad** (`Safe` 2 > `Pvp` 1). Con igual prioridad se queda la primera
  del archivo.
- **Consulta O(1):** `tx = (int)Math.Floor(x) - OriginX`, igual en y; fuera de la rejilla (o `Empty`) → 0 / `Normal`.
  Casilla `(tx, ty)` cubre `[tx, tx+1) × [ty, ty+1)`: el borde izquierdo/inferior es dentro, el derecho/superior fuera.
- **`BuildNpcCollision`:** `new MapCollisionGrid(map.Width, map.Height, blocked, map.OriginX, map.OriginY)` con
  `blocked[i] = map.IsTileBlocked(tileX, tileY) || casilla Safe` (comprueba en `MapCollisionGrid` el orden del
  índice: fila por fila desde el origen). Si no hay zonas seguras, devuelve `map` tal cual.
- **`ValidateSpawners`:** por cada spawner, con `r = WanderRadius + max(HalfWidth, HalfHeight)` de su tipo
  (`npcs.FindType`), recorre las casillas de `floor(X - r)..floor(X + r)` × `floor(Y - r)..floor(Y + r)`; si alguna
  es `Safe` → `InvalidOperationException("zones.json: el spawner <índice> (tipo <typeId>) toca la zona segura <id>; muévelo o cambia la zona.")`.

- `PlayerEntity` (`Entities/PlayerEntity.cs`, junto a `Gold` ~35): `public ushort ZoneId { get; set; }` (0) y

16. Reaparición dentro: con el punto de aparición en la ciudad, un jugador muerto fuera reaparece y emite `ZoneChanged(1, Safe)`.
17. Sin `ZoneMap` (constructor de siempre): ningún evento en 50 ticks moviéndose.

**Protocolo:** `ZoneList` ida y vuelta con 0 zonas (2 B) y con 32 zonas / 128 rectángulos con coordenadas negativas
(1154 B); `TryRead` rechaza N = 33, R = 0, R = 17, ΣR = 129, kind 0 y 3, id 0, `w` 0 y negativo, un byte de menos y
de más, tipo distinto; `Encode` lanza en los mismos casos. `ZoneChanged` ida y vuelta (1, Safe), (2, Pvp), (0, Normal)
en 4 B; rechaza (0, Safe), (1, Normal), kind 3, longitudes 3 y 5. `Version == 19`.

**Red:** con zonas y el punto de aparición en la ciudad, el cliente recibe `Welcome`, **inmediatamente después**
`ZoneList` con las zonas, y tras el primer tick `ZoneChanged(1, Safe)`; al moverlo fuera, `ZoneChanged(0, Normal)`
solo para él (otro jugador no lo recibe). Sin zonas no hay `ZoneList` (las pruebas existentes siguen igual).

**Config y bots:** `ServerConfig` por defecto `ZonesPath == ""`; `ResolveZonesPath` relativo a la configuración. Los
contadores de zona de `BotClient` suman bien sobre mensajes codificados (si hace falta, extrae el recuento a un método
`internal static` y pruébalo como `BotItemCatalogTests`).
